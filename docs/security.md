# 登录与安全行为

## 登录方式

GitHub OAuth 使用 GitHub 的 access token 和用户接口识别用户，不依赖 ID Token。密码账号使用 bcrypt，密码为 12–72 字节，每次登录必须再完成一种第二因素：

- TOTP：RFC 6238、SHA-1、六位数字、30 秒周期，容忍前后一个时间步。每台绑定设备使用独立密钥，已使用的时间步不会再次通过。
- 邮箱验证码：通过 Resend 发送，六位数字，五分钟有效，最多尝试五次，成功后作废。

密码注册先验证邮箱，再创建账号或初始化预置管理员密码。已有 GitHub 账号与密码账号不会仅凭相同邮箱自动合并。“账户安全”提供设置或修改密码、多邮箱绑定、主邮箱选择及多设备身份验证器管理。已有密码的账号修改安全设置时需要当前密码；尚未设置密码的 OAuth 账号使用已认证会话初始化凭据。邮箱修改必须验证新邮箱，验证码绑定当前用户和会话，五分钟内最多尝试五次。

绑定新邮箱不会替换当前主邮箱。每个邮箱只能绑定一个账号，已验证的绑定邮箱均可用于密码登录；邮件第二因素发送到本次输入的登录邮箱。OAuth 的 `userinfo` 和 OIDC ID Token 在 `email` scope 下仅提供主邮箱及其验证状态，不公开完整邮箱列表。主邮箱必须先切换到另一个已验证邮箱才能解绑，解绑的邮箱不能再用于该账号登录。

可为多台身份验证器分别命名，扫描各自的绑定二维码（或手动输入密钥），并提交实时验证码完成绑定；移除时需要所选设备的新验证码。没有 OAuth 登录或可用邮件第二因素时不能移除最后一台设备，以免失去登录方式。修改密码、绑定或解绑邮箱、切换主邮箱或移除身份验证器会撤销其他会话、待完成的登录挑战和应用授权，保留当前会话。

密码和第二因素未同时通过前不创建登录会话。验证码绑定当前浏览器挑战；密码尝试、邮件发送及 TOTP 绑定使用数据库计数限流。邮箱每分钟最多一次、每天最多 30 次；密码按来源和邮箱限制。

本版本不提供忘记密码重置或账号自动关联。注册关闭时，新账号不能创建。

## 用户管理

管理员可以修改其他用户的角色、按截止时间封禁、解封或删除账号。封禁立即撤销已有会话、登录挑战和应用授权，并阻止密码与 OAuth 登录；到期或解封后需要重新登录，旧凭据不会恢复。删除同时清除该用户的应用和相关授权数据。管理员不能删除或封禁自己，也不能将自己降为普通用户；操作时再次在数据库事务中检查管理员身份。

## OAuth 边界

普通 OAuth 2.0 客户端无需 nonce 或 issuer 校验。机密客户端可选择 S256 PKCE，公开客户端必须使用。注册时不校验回调 URI 的格式、协议、域名或路径；授权时按注册的原始字符串完整匹配，没有通配符匹配。授权码兑换仍绑定原始回调值，注册不会授予任何用户权限。

[OpenID Connect](oidc.md) 请求额外校验回调 URI，并将 nonce 绑定到授权请求和签名 ID Token。客户端必须验证签名、issuer、audience、有效期及传入的 nonce。签名私钥保存在 ConfigCenter 的密钥设置中，JWKS 只公开公钥；ID Token 有效期为五分钟，退出登录或撤销授权不会立即撤销已经签发的 ID Token。

```text
业务应用 → /oauth/authorize → 登录 → 用户同意 → 已登记回调
业务应用 → /oauth/token → access_token → /oauth/userinfo
```

用户同意请求绑定浏览器、会话和 CSRF，并且只能提交一次。授权码绑定客户端、回调和可选 PKCE。授权码及令牌在数据库只存摘要；TOTP 密钥使用 AES-256-GCM 加密，短邮箱验证码使用带应用密钥的 HMAC。

刷新令牌轮换保留重放检测记录；重复使用旧凭据会撤销整组授权。用户或客户端撤销、删除应用均会立即使相应访问令牌失效。管理接口只接受浏览器会话，业务应用访问令牌无法操作管理接口。

## 部署

生产使用 HTTPS。Cookie 依据配置的公网 HTTPS 地址标记 Secure，支持 TLS 在反向代理终止；不信任任意来源的转发 IP 标头，因此反向代理后的密码来源限流会按代理地址共享计数。数据库需与 configcenter 独立，配置中心 API 密钥需限制到专属项目。

GitHub、Resend 和配置中心的真实凭据不包含在仓库中。自动测试使用模拟服务；上线前应使用实际 GitHub 应用、已验证 Resend 发件域和真实配置中心完成一次登录及授权验收。
