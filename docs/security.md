# 登录与安全行为

## 登录方式

GitHub OAuth 使用 GitHub 的 access token 和用户接口识别用户，不依赖 ID Token。密码账号使用 bcrypt，密码为 12–72 字节，每次登录必须再完成一种第二因素：

- TOTP：RFC 6238、SHA-1、六位数字、30 秒周期，容忍前后一个时间步。已使用的时间步不会再次通过。
- 邮箱验证码：通过 Resend 发送，六位数字，五分钟有效，最多尝试五次，成功后作废。

密码注册先验证邮箱，再创建账号或初始化预置管理员密码。已有 GitHub 账号与密码账号不会仅凭相同邮箱自动合并。登录后在“账户安全”输入当前密码，复制密钥到身份验证器，并提交实时验证码完成 TOTP 绑定。邮箱验证仍可作为备用方式。

密码和第二因素未同时通过前不创建登录会话。验证码绑定当前浏览器挑战；密码尝试、邮件发送及 TOTP 绑定使用数据库计数限流。邮箱每分钟最多一次、每天最多 30 次；密码按来源和邮箱限制。

本版本不提供密码重置、TOTP 解绑或账号自动关联；需保留邮箱登录能力。注册关闭时，新账号不能创建。

## OAuth 边界

普通 OAuth 2.0 客户端无需 nonce 或 issuer 校验。机密客户端可选择 S256 PKCE，公开客户端必须使用。回调 URL 完整匹配，不支持通配符；不接受 `javascript:`、凭据 URL 或 fragment。

```text
业务应用 → /oauth/authorize → 登录 → 用户同意 → 已登记回调
业务应用 → /oauth/token → access_token → /oauth/userinfo
```

用户同意请求绑定浏览器、会话和 CSRF，并且只能提交一次。授权码绑定客户端、回调和可选 PKCE。授权码及令牌在数据库只存摘要；TOTP 密钥使用 AES-256-GCM 加密，短邮箱验证码使用带应用密钥的 HMAC。

刷新令牌轮换保留重放检测记录；重复使用旧凭据会撤销整组授权。用户或客户端撤销、删除应用均会立即使相应访问令牌失效。管理接口只接受浏览器会话，业务应用访问令牌无法操作管理接口。

## 部署

生产使用 HTTPS。Cookie 依据配置的公网 HTTPS 地址标记 Secure，支持 TLS 在反向代理终止；不信任任意来源的转发 IP 标头，因此反向代理后的密码来源限流会按代理地址共享计数。数据库需与 configcenter 独立，配置中心 API 密钥需限制到专属项目。

GitHub、Resend 和配置中心的真实凭据不包含在仓库中。自动测试使用模拟服务；上线前应使用实际 GitHub 应用、已验证 Resend 发件域和真实配置中心完成一次登录及授权验收。
